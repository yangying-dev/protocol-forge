# 人工手动测试用例（Manual Test Cases）

**适用版本**：当前工作区（未提交的 v0.2.0 前状态；含本 session 全部改动与 A 类三件）
**对象**：人工 QA —— 维护者本人在真实桌面环境逐条执行
**配套文档**：[`FullFunctionTest.md`](FullFunctionTest.md)（代码面/服务验收，含自动化证据）、[`RealDeviceQA.md`](RealDeviceQA.md)（真机发送专项）

---

## 0. 文档说明

### 目的与范围

本手册把「当前已有特性」组织成 **按用户操作流** 的逐条可执行用例，供人工在真机上走查 GUI、CLI 与交互细节。它与 `FullFunctionTest.md` 的分工：

| | FullFunctionTest.md | 本手册 |
|---|---|---|
| 组织方式 | 按内部服务/代码面（T-xx/S-xx/H-xx…） | 按用户操作流（MT-xx） |
| 形式 | 验收判据 + §24 优先级索引 | 逐步步骤 + 预期 + 勾选记录 |
| 读者 | 贡献者/评审 | 手动 QA 执行者 |

### 使用方式

- 逐条执行，**每条末尾勾选**：`☐ 通过` / `☐ 失败`（失败另记现象与 trace.log 线索）。
- 用例之间大多独立，可乱序；标注「前置」的必须先做。
- **发送用例注意安全**：遵循 [RealDeviceQA.md](RealDeviceQA.md) 顶部的数据安全规则；优先用回环/测试网卡，对端自行抓包回环验证。
- 全部完成后填写 §5 记录表。

### 通过标准

- 步骤给出确切路径/快捷键/控件名；预期给出可观察结果（文字、颜色、状态、文件字节）。
- **不要求每条成功** —— 失败本身就是发现；记录即价值。

## 1. 测试准备

### 1.1 构建与回归基线

```bash
dotnet build            # 必须 0 警告 / 0 错误
dotnet run --project tests/pf-verify   # 回归基线：ALL GROUPS PASS（378 断言）
```

> 手工测试前先跑一次 harness，确认基线绿再动手。

### 1.2 生成合成抓包（可复制、可重复）

```bash
python3 docs/make-synthetic-capture.py /tmp/pf-manual.pcap
```

生成的 6 帧合成抓包（PFCP / GTP-U / TCP/HTTP）用于绝大多数用例。**真实抓包留在本机，不进仓库**（`.gitignore` 与 CI 拒绝 `*.pcap`/`*.pcapng`）。

### 1.3 平台与前置

| 平台 | 前置 | 说明 |
|---|---|---|
| Windows | Wireshark/tshark ≥ 2.6.0；Npcap（发送 L2，可选） | 出口锁定用例（MT-K11）仅在无 Npcap 时出现告知 |
| Linux | tshark ≥ 2.6.0 | AF_PACKET 需 root 才能真发 |
| macOS | tshark ≥ 2.6.0；`/dev/bpfN`（发送 L2，可选） | — |

> tshark 不在 PATH 时可用 `TSHARK_PATH` 环境变量，或在应用内「文件 → tshark 路径…」指定。

### 1.4 环境变量

| 变量 | 用途 |
|---|---|
| `TSHARK_PATH` | 覆盖 tshark 可执行文件位置（优先于已保存的路径设置） |

#### MT-B1 正常 tshark：全文可编辑

- **步骤**

- **预期**：不弹编辑器；**状态栏显示 `Not editable: …` 及原因**（六检查：字段类型/字节跨距/字节对齐/帧内/字节证据/字节一致性）。

### G. 保存 / 导出

#### MT-G1 覆盖保存
- **前置**：打开文件后做了一次编辑。
- **步骤**：Ctrl+S。
- **预期**：原位写回 PCAP；此后再次编辑，撤销历史/脏标记语义正确。
  记录：☐ 通过　☐ 失败

#### MT-G2 导出为
- **步骤**：Ctrl+Shift+S，选 `.pcap` 路径。
- **预期**：写出 PCAP 文件；用 tshark `tshark -r out.pcap` 可正常读取且包含修改后的字节。
  记录：☐ 通过　☐ 失败

#### MT-G3 PCAPNG 写回保真
- **前置**：一个 `.pcapng` 源文件（或先用「导出为 .pcapng」制造一个）。
- **步骤**
  1. 打开该 pcapng → 编辑某包 → 导出为 **.pcapng**（Ctrl+Shift+S 选 `.pcapng`）。
  2. 命令行：`tshark -r 原始文件 -T fields -e frame.time_epoch` 对比 `tshark -r 导出文件 -T fields -e frame.time_epoch`。
- **预期**：导出文件是 PCAPNG（`tshark -r` 开头 magic 为 `0a0d0d0a`）；**时间戳与原始一致**（纳秒源不要出现 1000 倍偏差）；接口描述/时间分辨率保留。
  记录：☐ 通过　☐ 失败

#### MT-G4 格式随扩展名
- **步骤**：同一文件分别导出为 `.pcap` 与 `.pcapng`。
- **预期**：`.pcap` → classic PCAP（tshark 头部 magic `d4c3b2a1`/`a1b2c3d4`）；`.pcapng` → PCAPNG；互不串格式。
  记录：☐ 通过　☐ 失败

#### MT-G5 导出后重开
- **步骤**：导出 → 关闭窗口 → 重新打开导出文件。
- **预期**：修改后的字节、时间戳、包数完整保留；若要恢复原状，需重开原始文件（导出不改变源）。
  记录：☐ 通过　☐ 失败

### K. 发送（工具栏 + 发送通道）

> 发送安全：优先回环与测试网卡；需要验证「到了线上」的对端自抓包。

#### MT-K1 网卡枚举与重扫
- **步骤**：打开应用，观察适配器下拉；点「重新扫描」。
- **预期**：下拉列出本机非回环网卡（回环殿后）；重扫后原选择被保留恢复。
  记录：☐ 通过　☐ 失败

#### MT-K2 发送门禁（Start 禁用态）
- **步骤**：分别在以下状态观察「▶ 开始」按钮可用性：
  1. 未勾选任何包；
  2. 只读模式（见 MT-B2）；
  3. 只选了回环网卡；
  4. 正在发送中。
- **预期**：四态下「开始」均禁用；回环单选时若强行触发发送（若可达），状态栏提示拒绝（BlockedLoopback 类文案）。
  记录：☐ 通过　☐ 失败

#### MT-K3 单包发送闭环
- **前置**：本机有能力自抓（或对端抓包机）。Linux 无 root 时 UDP 兜底仍应「成功」。
- **步骤**：勾选 1 包 → 选网卡 → ▶ 开始。
- **预期**：✓ 计数为发送次数、✗ 为失败数；状态栏显示目标网卡与实际发送；右键「导出发送历史」含该行记录。
  记录：☐ 通过　☐ 失败

#### MT-K4 间隔 / 循环 / 暂停 / 停止
- **步骤**：间隔 500 ms、循环 3 次，勾选 2 包 → 发送 → 中途暂停 → 继续 → 停止。
- **预期**：发送节奏约 500ms/次；暂停即停、按钮文字变「继续」；继续续跑；停止立即结束并给出累计计数。
  记录：☐ 通过　☐ 失败

#### MT-K5 发送计数正确
- **步骤**：2 包 × 循环 3 = 6 次发送，观察 ✓。
- **预期**：✓ 最终 = 6（= 包数 × 循环数；多网卡时为包数 × 循环 × 目标数）。
  记录：☐ 通过　☐ 失败

#### MT-K6 Auto-fix 修复
- **步骤**：勾选 Auto-fix 后发送一个源 IP 与网卡不符/UDP 校验和错误的包；对端或回环抓包观察。
- **预期**：IPv4/IPv6、TCP/UDP 校验和被重算；源地址被改写为本网卡地址（对端抓包可见）。
  记录：☐ 通过　☐ 失败

#### MT-K7 VLAN 模式四态
- **步骤**：VLAN 下拉依次选：保持原样 / 插入 / 替换 / 剥离，观察 ID 输入框；配合适配器选择发送。
- **预期**：插入/替换时显示 VLAN ID 框（默认 100），保持/剥离时隐藏；**发送后包内字节未被原地改写**（hex 编辑器无新增橙色标记 —— 标签操作作用于副本）；对端可见对应标签/剥离效果。
  记录：☐ 通过　☐ 失败

#### MT-K8 多网卡扇出
- **前置**：≥ 2 个可用非回环网卡（无则跳过）。
- **步骤**：勾选「多网卡」→ 观察状态栏目标摘要 → 勾选 1 包发送。
- **预期**：状态栏先显示 `n×[网卡列表]`；发送时每包对每目标恰好一次；✓ 计数 = 包数 × 目标数。
  记录：☐ 通过　☐ 失败

#### MT-K9 发送历史与清空
- **步骤**：完成发送后开右键菜单 → 查看「发送历史」存在 → 点「清除发送历史」。
- **预期**：历史逐包记录（含失败原因文案）；清除后右键导出项禁用（空历史）。
  记录：☐ 通过　☐ 失败

#### MT-K10 右键单发忽略复选框
- **步骤**：不勾选任何包，选中一行 → 右键「发送此报文」。
- **预期**：**仍可发送**当前行（与工具提示「发送当前选中行」一致）—— 复选框只影响工具栏 ▶ 开始。
  记录：☐ 通过　☐ 失败

#### MT-K11 【A 类专项】Windows 出口锁定告知
- **前置**：Windows 真机，且未安装 Npcap（或用不提供 L2 的安装）。
- **步骤**：选一个非回环网卡 → 勾选 1 包 → 发送。
- **预期**：状态栏出现**出口无法锁定告知**（`Send.EgressNotPinnable` 文案：Windows 普通 socket 无 SO_BINDTODEVICE/IP_BOUND_IF 等价手段，内核可能走其它网卡，建议装 Npcap）；发送仍降级可用（UDP/IP 路径），✓ 计数照常。
- **对照**：安装 Npcap 后同样操作不出现该告知。
  记录：☐ 通过　☐ 失败

#### MT-K12 只读态发送被拒
- **前置**：处于 MT-B2 只读态。
- **步骤**：尝试 ▶ 开始与右键发送。
- **预期**：两入口均拒绝，状态栏给出只读说明；SendHistory 无新增发送行。
  记录：☐ 通过　☐ 失败

### M. 无头 CLI

> CLI 分支在 Avalonia 启动前，四个动词：`validate` / `edit` / `send` / `stats`。退出码 0=成功、1=失败、2=用法错误。

#### MT-M1 validate
- **步骤**：`dotnet run --project ProtocolForge -- validate /tmp/pf-manual.pcap`（发布版为 `ProtocolForge validate <file>`）；再试不存在的文件。
- **预期**：合法文件 exit 0 且输出结构摘要；不存在文件 exit 1。
  记录：☐ 通过　☐ 失败

#### MT-M2 edit
- **步骤**：`ProtocolForge edit <file> 1 'ip.src=10.0.0.99'`（帧 1 改源 IP）→ 用 tshark 或 validate 复查。
- **预期**：编辑经同一 Verify-Before-Commit 事务；成功 exit 0，输出新值落点；改动不改变帧长。
  记录：☐ 通过　☐ 失败

#### MT-M3 send
- **步骤**：`ProtocolForge send <file> --int <网卡名>`（先小包数）。
- **预期**：按发送阶梯发送并报告每包结果；无权限/回环/只读等被守卫拦截时给出原因而非崩溃。
  记录：☐ 通过　☐ 失败

#### MT-M4 stats
- **步骤**：`ProtocolForge stats <file> conv,ip`。
- **预期**：输出 tap 文本；注意 tap 忽略 `-Y`（过滤器要放进 tap 参数）。
  记录：☐ 通过　☐ 失败

#### MT-M5 --help
- **步骤**：`ProtocolForge --help`。
- **预期**：打印用法并 **exit 2**（不启动 GUI 窗口）。
